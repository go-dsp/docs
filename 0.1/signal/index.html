signal

Filter design and filtering, spectral estimation, resampling and peak finding, with the semantics of SciPy's scipy.signal.

You are reading the documentation of an outdated version, whose text may no longer be accurate. Go to the latest version.

Signal processing in pure Go (CGO_ENABLED=0): filter design and filtering, spectral estimation, resampling and peak finding, with the semantics of SciPy’s scipy.signal and, where it differs, a note on MATLAB’s.

import "github.com/go-dsp/signal"

z, _ := signal.Butter(8, []float64{0.2}, signal.Lowpass, nil) // zeros, poles, gain
sos, _ := z.SOS(false)                                        // second-order sections
y, _ := signal.SOSFiltFilt(sos, x, nil)                       // zero-phase filtering
f, p, _ := signal.Welch(x, &signal.SpectralOptions{Fs: 1000, Nperseg: 1024})

The module is github.com/go-dsp/signal, BSD-3-Clause. It depends on go-fft/fft (transforms and the classic windows), go-numerics/special (complete elliptic integrals, I0) and go-simd/floats (the assembly dot product used by the FIR kernels).

remez.go’s exchange follows the Parks–McClellan program of J. H. McClellan, T. W. Parks and L. R. Rabiner (IEEE Trans. Audio Electroacoust., 1973) as SciPy’s _sigtoolsmodule.cc carries it in E. Kvaleberg’s C translation (SciPy License, BSD-3-Clause; Copyright 2005 Travis Oliphant and the SciPy developers); its control flow and label numbers are kept so the two read side by side.

Conventions

  • Signals and coefficients are []float64; filters have real coefficients and signals are real and one-dimensional (no axis argument: loop over the channels of a matrix).
  • A filter is a ZPK (zeros, poles, gain), a transfer function (b, a) or an SOS (second-order sections). Use SOS above order 8: the transfer function form loses accuracy fast (see docs/verification.md).
  • Functions that can fail return an error; nothing panics on bad arguments (the fuzz targets enforce it), and sizes are bounded (2^28 elements) so absurd arguments fail instead of exhausting memory.
  • Option structs have useful zero values: nil means SciPy’s defaults. Where SciPy’s default differs between functions (detrend, scaling) the zero value is “the default of this function”.

Differences worth knowing:

  • STFT/ISTFT follow SciPy’s legacy stft/istft (the ShortTimeFFT class is not provided).
  • SciPy emits warnings where Go returns values: a singular group delay is set to zero silently; Remez returns the best filter together with ErrNotConverged (SciPy raises; a degenerate design whose taps would not be finite returns nil).
  • EllipAP returns an error (SciPy returns NaN poles) when the stopband attenuation is below the passband ripple.
  • Bessel prototypes use exact integer polynomial coefficients refined in 320-bit arithmetic (double precision loses the zeros above order 8) and are limited to order 150, where the delay gain overflows float64.
  • The PadModeReflect, PadModeAntireflect, PadModeSmooth and PadModeLine extensions of a one-sample signal are undefined in SciPy; here they repeat the sample.

Not provided: N-dimensional and axis variants, complex-coefficient filters, dlti/lti classes, ShortTimeFFT, savgol_filter, czt, continuous wavelets and find_peaks_cwt (wavelets are planned in this organisation).

Verification

SciPy 1.18.1 with NumPy 2.5.4 is the oracle, driven from Go (oracle_test.go: one persistent Python process, base64 float64/complex128 over JSON lines, so no decimal round trip loses a bit). Every comparison is recorded in testdata/oracle and replayed from there, so go test needs no Python and the same recorded SciPy output is checked on every architecture CI runs. GOWORK=off go test -update ./... re-records it and rewrites docs/accuracy.md, the table of maximum ULP errors, normwise relative errors and exact-equality counts for 225 groups of values; docs/verification.md explains the measures and the few places where SciPy itself is the less accurate side (ill-conditioned elliptic and Bessel designs, high-order transfer functions).

  • 100% statement coverage with -race, including the error paths.
  • gofmt, go vet, govulncheck; amd64, arm64, 386 (and under qemu riscv64, loong64, ppc64le, s390x, arm) and every GOOS/GOARCH pair compiling the tests.
  • Fuzz targets for the design constructors, the spectral estimators, the convolutions and the peak finder.

Performance

docs/perf.md: one core against SciPy on the same host, in interleaved rounds, with the load average checked (-perf -perfcase <regexp> measures a subset without rewriting the table). The FIR kernels call the SIMD dot product of go-simd/floats; the recursions are serial by nature, so SOSFilt runs four (or two) sections sample-major to overlap their dependency chains and the FIR form of LFilter is a direct chain eight outputs wide, both bit-identical to the one-section, one-output form. Remez runs the McClellan–Parks–Rabiner exchange (its search walks the error curve from each extremum instead of evaluating the whole grid every iteration), PeakProminences finds every base in two monotonic-stack passes (O(n), where the per-peak scan SciPy uses is O(n·peaks)), and Spectrogram computes its PSD through one reused spectrum buffer.
